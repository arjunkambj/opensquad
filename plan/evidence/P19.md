## Design invariants (all enforced inside the writing transaction)

- One lead per `(campaignId, canonicalDomain)` — P21's importer, untouched.
- One ACTIVE booking per lead — at most one `proposed`/`confirmed` row,
  read through `by_prospectId_and_state` in the same transaction as the
  insert/move.
- OCC everywhere mutable — `expectedVersion` on `updateStage`/`assign`/
  `setNextAction` and every booking transition; `propose` takes the LEAD's
  version because it writes the lead row too.
- Idempotent by request — every public mutation takes `requestId`; the
  committed `leadEvents` row's `operationKey` IS the idempotency record.
  A replayed request returns the row it produced; the same key carrying
  different content is `CONFLICT`.
- Stage discipline — automatic writers (`markSendAccepted`, `markReplied`)
  only advance (`advancedStage` refuses regression) and never enter or exit
  `won`/`lost`. Human `updateStage` owns terminal entry AND exit, always
  with `reason`. `booking_proposed`/`booked` are reachable by human update
  only when the matching live booking exists; the real path is
  send-acceptance → `booking_proposed`, confirm → `booked`.
- `lastContactedAt` only from an accepted send fact (`recordSendOutcome`'s
  acknowledged branch). `lastReplyAt` only from a verified inbound on a
  lead-bound thread. Both stamp max(existing, fact) — never rewind.
- Business write + `leadEvents` insert in ONE transaction, always.
- Manual confirmation only — `confirm` requires the agreed start/end, a
  valid IANA timezone, and a non-empty `confirmationNote` (the basis).
  `confirmationSource` is `manual`; `externalEventRef` stays unset — there
  is no provider event to reference. A proposal, a clicked link, an
  ambiguous reply and a model classification are all still `proposed`.
- Outcomes are recorded after the fact — `recordOutcome` refuses before the
  agreed start; `completed`/`no_show` both keep the agreed times as the
  record of what was booked.
- Reschedule/cancel retires stale proposals — `retireLinkedDrafts` walks
  `drafts.by_bookingId`, supersedes every unsent revision, retires its open
  `draft_approval` ask and cancels its parked send intents via the owning
  internal paths; a revision that already reached the provider stays as
  history.
