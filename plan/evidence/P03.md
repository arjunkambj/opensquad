## Verified SDK surface (installed reality vs plan)

`@asciidev/box-sdk@0.0.34` is an OpenAPI-generated client; real exports checked,
no signatures guessed:

- `new BoxApi(new Configuration({ accessToken }))` → `Authorization: Bearer`
  against `BASE_PATH = https://ascii.dev/api/box/v1`.
- `create({ idempotencyKey, createBoxRequest })` sends the `Idempotency-Key`
  header natively — **no raw-fetch fallback was needed**. `createBoxRequest`
  carries `noEnv`, `ttlSeconds`, `env`, `from`, `type`, `setupScript`.
- `get` → `BoxInfoResponse`; `Box.state` ∈ `init|provisioning|provisioned|
  cloning|ready|idle|running|archiving|archived|error`.
- `command` (sync ≤600 s or `detached` + `commandStatus` poll) covers
  bootstrap. Detached start returns `type: "command.started"` + `processId`.
- `resume({ resumeRequest })` accepts `noEnv`/`ttlSeconds`;
  `update({ updateBoxRequest: { ttlSeconds } })` is the PATCH TTL-extend.
- `stop({ stopRequest: { force? } })` = pause/archive (refused while a
  snapshot save fails, per SDK docs — adapter records `uncertain`).
- `deleteBox` **requires** `xAsciiConfirmDelete` equal to the target `boxId`
  (mismatch → 409); returns a `DeletionOperation` polled via
  `getDeletionOperation`. This confirm-header requirement is a delta vs the
  plan table (plain `DELETE /boxes/{id}`) — now encoded in the adapter.
- `box-helpers.waitUntilReady` exists in the SDK but the adapter implements
  its own bounded poll to keep `archived`/`error`/timeout outcomes explicit.
- `Box.desktopUrl`/`url` can embed tokens — `sanitizeBox` strips them; only
  id/state/environment/timestamps are persistable.

Codex protocol types were generated from the INSTALLED binary (not copied):
`ClientRequest` confirms `initialize`, `account/read`, `account/login/start`
(`chatgptDeviceCode`), `account/login/cancel`, `account/logout`,
`account/rateLimits/read`, `thread/start`, `thread/resume`, `turn/start`,
`turn/interrupt`; `ServerNotification` confirms `account/login/completed`,
`turn/completed`, `error`, `account/updated`, etc. `LoginAccountResponse`
device-code variant carries `loginId`, `verificationUrl`, `userCode`.
`ClientNotification` = `initialized`. Server-initiated requests (approval
prompts, `chatgptAuthTokens/refresh`, `attestation/generate`, MCP elicitation)
are answered by a policy handler that declines/refuses — the worker also sets
`approvalPolicy: "never"` + read-only sandbox on thread/turn start.
