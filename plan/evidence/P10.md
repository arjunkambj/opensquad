# P10 — Exact drafts, approval and safe sending

Date: 2026-09-14. Executor: subagent-P10.
Base revision: `cc62d47` (P05/P06 integrated). Task branch: `opensquad/P10`,
worktree `opensquad-worktrees/P10`.
Toolchain: pnpm `11.21.0`, `convex 1.45.0`, `@convex-dev/workflow 0.4.7`.

Implements architecture §8 / §4.3 / §4.4 — the send boundary: immutable draft
revisions, revision+context-bound human approvals, durable send-intent
reservation, a single guarded AgentMail request, honest uncertainty and
reconciliation, atomic usage accounting, suppression/duplicate/takeover/window
protections, and verified provider-event receipts.

Probes ran against an **isolated local backend** (`opensquad-p10`, port 3212 —
the worktree's configured 3214 was occupied by P07's backend, so the local
deployment config was repointed to the live 3212/3213 pair) using synthetic
`--identity` subjects and two **controlled** AgentMail inboxes
(`opensquad-p05-probe@` sender → `repulsivebicycle137@` recipient). All sends
below are real provider calls between those controlled inboxes only.

## Contract decisions

1. **Exactly one commit point.** `beginDispatch` is the only transition to
   `requesting`; after it commits the provider request cannot be retracted.
   All gates (liveness, exact approval+context binding, policy/brief version,
   conversation state, takeover, inbox binding, suppression, duplicate-attempt
   guard, §8.7 covering decision) run inside that one transaction; the window
   and capacity checks run last so a parked attempt never debits the wrong
   local day.
2. **One controlled action, no retries.** `sendApprovedDraft`/`dispatchAttempt`
   run outside Workflow/component retry machinery (`retry: false`); the
   provider idempotency key is minted once at reservation and never re-minted.
   Uncertainty is a first-class durable state, not a retry loop.
3. **Reconciliation replays, never recreates.** Same key + same exact payload +
   same endpoint + same parent message. Policy is re-checked first — a replay
   that would now violate policy routes to `needs_review`/stays `uncertain`.
4. **Usage follows the attempt lifecycle.** Reserve at the commit point;
   commit on `accepted`; release on definitive refusal; `uncertain` keeps the
   debit blocked until reconciliation resolves it.
5. **Approvals are immutable verdict rows** bound to revision+hash+recipient+
   contextVersion; stale approvals can never silently apply to newer content.
6. **Receipts dedupe twice** — `providerEventId` for delivery dedupe and
   `(workspaceId, applicationKey)` for business-effect dedupe; a component
   callback firing is never treated as proof of application handling.
