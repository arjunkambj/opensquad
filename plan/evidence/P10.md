## Verification (probes, isolated local deployment)

### V13 — exact draft/approval conflict behavior

| Probe | Result |
|---|---|
| `approvals:approve` with `expectedVersion:99` on open decision (v1) | **CONFLICT** `decision version is 1, not 99` |
| `approve` with correct version | `verdict: approved`, approvals row stores draftId + payloadHash + normalizedRecipient + contextVersion=2; decision `resolved` v2, `answer.fields.draftResolution="approved"`, `resolvedBy` = owner identityKey |
| `approve` replay with same `requestId` | `replayed: true` — same approvals row returned, no second resolution |
| `approve` second time with different `requestId` | **CONFLICT** `decision is already resolved — a prior resolution stands` |
| `drafts:revise` on approved rev1 | new immutable rev2 (`supersededAt` set on rev1), old open decision superseded, new `draft_approval` decision opened bound to rev2 |
| `revise` replay with same `requestId` | recorded revision returned — no second decision, no second row |
| `approvals:requestChanges` | `verdict: rejected`, decision answer `approved:false` + `fields.draftResolution="changes_requested"` + comment body |
| `approvals:reject` | `verdict: rejected`, `fields.draftResolution="rejected"` + reason |
| `revise` with no changed field | **INVALID** `revise requires at least one of recipient/subject/body` — no-op revisions cannot mint a new hash |

## Contract notes for P11/P13

- `sending:preflight` is the member-facing "why not yet" surface — full gate
  list plus `attempts` with `resultCode` (`sent`/`pending`/`rejected`/
  `definitely_unsent`/`delivery_uncertain`).
- `approvals.approve` schedules `sendApprovedDraft`; `sending:requestDispatch`
  is the explicit re-trigger (both converge on the same idempotent gates).
- `sending:resolveDeliveryUncertainty` is the ONLY replacement path —
  reviewer supplies the current replacement draft + explicit
  `acknowledgeDuplicate:true`; the decision answer records the full binding.
- `internal.sendAttempts.recordProviderEvent` is the verified-event write
  path (P11's webhook handler calls it; P10 already wires it from
  `onEvent`/`onMessageReceived`). Pending inbound receipts are P11's input.
- A `delivery_uncertain` decision resolved WITHOUT replacement leaves the
  conversation send-blocked by design — the honest "unknown, reviewed"
  record; only a bound replacement can dispatch.
- Drafts whose workspace `policyVersion` or conversation `contextVersion`
  moved on can never dispatch — they need `revise` + fresh approval.

## Known limitations / notes

- The demo-recipient gate (`demo_recipient_blocked`) is code-verified but
  not exercised live: P02 provides no demo-workspace provisioning toggle.
- `brief_changed` (campaign brief version) is implemented in
  `evaluateSendGates`; not probed separately (same mechanism as
  `policy_changed`).
- `AGENTMAIL_BASE_URL` override was used to synthesize transport failures;
  restored to default afterwards. `AGENTMAIL_API_KEY`/`FIRECRAWL_API_KEY`/
  `VITE_HEXCLAVE_PROJECT_ID` set on the local deployment only.
- The AgentMail component's retrying `sendMessage`/`reply` workpool path is
  NOT used for approved sends (it cannot satisfy one-attempt + preflight);
  the app-owned direct REST boundary performs dispatch. The component still
  owns inbound webhook verification + message mirroring.
