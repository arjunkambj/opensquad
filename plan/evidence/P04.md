## Inspection findings — installed `@firecrawl/firecrawl-convex@0.1.1`

Verified against `dist/` + `src/component/` (not docs):

- `FirecrawlClient` methods: `scrape`, `map`, `search`, `startCrawl`,
  `getCrawl`, `getCrawlByJobId`, `listCrawls`, `listPages`, `getPage`,
  `cancelCrawl`, `deleteCrawl`, `resumeCrawl`.
- `scrape(ctx, url, opts)` → `POST {FIRECRAWL_API_URL}/v2/scrape`; failures
  raise `ConvexError {code:"firecrawl_request_failed", status, path,
  message}`; transient 408/425/429/5xx retried ≤3 honoring `Retry-After`.
- The component **self-mounts** `POST {httpPrefix}webhook` from its own
  `httpRouter` — `app.use(firecrawl, { httpPrefix: "/firecrawl/" })` serves
  `<site>/firecrawl/webhook` with no app-side route. `convex/http.ts`
  deliberately adds nothing for it (comment updated).
- The webhook is **double-guarded** (src/component/http.ts):
  1. `X-Firecrawl-Signature: sha256=<hex>` HMAC over the raw body when
     `FIRECRAWL_WEBHOOK_SECRET` is set → 401 on mismatch. **Caveat: when the
     secret is unset the HMAC check is skipped entirely** — deployments must
     always set it.
  2. A per-crawl `x-firecrawl-convex-token` handed to Firecrawl at webhook
     registration; `handleWebhook` compares it timing-safely against the
     crawl row → 401 "bad token" on mismatch.
  3. Unknown crawlId/jobId → `{accepted:true, reason:"unknown crawl"}` →
     200, deliberately ACKed so Firecrawl stops retrying strays.
- Crawl rows cap page bodies at Convex's 1 MB document limit
  (`truncated:true`, `unstored` count) — never silently.
- `crawl.start` supports `mode:"poll"` for deployments Firecrawl cannot
  reach (local dev) — the documented poll fallback.
- **Same Convex-1.45 ctx type skew as P05's AgentMail**: component ctx types
  resolve to `(fn, args, options?:{transactionLimits})` while real ctxs
  expose `OptionalRestArgs`. The wrapper adapts runners positionally
  (verified the component only calls `runX(fn, argsObject)`).

### URL admission guard (all verified live — rejected before any provider call)

| Input | Result |
|---|---|
| `ftp://example.com` | `URL scheme must be http(s)` |
| `https://user:pw@example.com/` | `credential-bearing URLs are not allowed` |
| `https://localhost/` | `local hostname not allowed` |
| `http://127.0.0.1/x` | `private/reserved IPv4 not allowed` |
| `http://192.168.1.1/` | `private/reserved IPv4 not allowed` |
| `https://[::1]/` | `private/reserved IPv6 not allowed` |

Residual limitation (documented for P09): Convex actions cannot resolve DNS,
so a public hostname rebinding to a private IP is not caught here; the guard
is policy enforcement, not full SSRF defense — provider-side fetch still
runs on Firecrawl's infrastructure.

## OAuth/callback constraints recorded for P07/P09

  is browser+loopback; in a headless Box the owner must paste the final
  redirect URL back (the `P04_CALLBACK_URL.txt` relay implements this).
  Newer CLI releases ship `--no-browser`; upgrading the Box-side pin is a
  P07 decision.
- App Server exposes `mcpServer/oauth/login` (returns `authorizationUrl`),
  `mcpServerStatus/list`, `mcpServer/tool/call`, and the
  `mcpServer/oauthLogin/completed` notification — the probe drives these.
- Whether Apollo MCP tokens auto-refresh, where they persist in CODEX_HOME,
  and whether partner app registration is required for customer-hosted use
  are **all still unverified** — the deferred probe is the only honest way
  to find out; P07 must not assume refresh or skip registration.
