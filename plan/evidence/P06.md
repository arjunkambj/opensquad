## Contract decisions

1. **Workflow owns durable ordering and waits.** `missions.create` starts
   exactly one `devFixtureMissionWorkflow` (`startAsync`) and stores the
   serializable ID; `onComplete` reconciles the mission record. Worker/app
   records are receipts — there is no second engine in app tables.
2. **Decisions are first-class, not messages.** `openRequiredDecision`
   creates the row AND a backend-owned continuation event bound to the
   workflow + generation inside one transaction; `resolve` records the
   answer, bumps the decision version, recomputes the mission's
   `requiredDecisionCount`/board column and sends the signal transactionally.
   `continuationSentAt` marks delivery; `redeliverContinuation` is the
   idempotent repair path. A second send attempt hits the component's
   already-delivered error and is folded into idempotent success.
3. **Comments never resolve approvals.** `addComment` writes only
   `missionComments`; `resolve` reads only `decisions` rows. A comment may be
   acknowledged by a run (`acknowledgedByRunId`) as guidance — never approval.
4. **Board column is derived, not draggable.** `boardColumnForMission` maps
   state → column; `requiredDecisionCount > 0` pulls active/waiting cards to
   `needs_you`; paused/cancelled/completed keep explicit badges.
5. **Prospect branches are replay-safe.** `(missionId, prospectId)` is the
   stable child-start key; a replayed `registerBranches` reuses the row and
   its pre-created completion event — no duplicate child workflows.
   `finalizeBranch` writes the outcome and signals the parent atomically;
   `onProspectWorkflowComplete` guarantees a recorded outcome (explicit
   `failed`/`cancelled` when the child errors or is cancelled), so the parent
   never waits forever.
6. **Expected-version on every mutating call**, `requestId` dedupe on
   create/resolve; `NOT_FOUND` hides cross-workspace; `FORBIDDEN` on
   insufficient role; anonymous/foreign issuers rejected.

## Gaps / notes for integrators

- **`waiting_for_runtime`** is plumbed (transitions + board mapping) but not
  exercised by the dev fixture — it's the worker-uncertainty state P10/P11
  use; the fixture never produces it.
- **`cancelChildWorkflows`** is defensive — in probes both fixture children
  completed before the parent's decision wait, so the in-flight-child cancel
  path was code-reviewed but not exercised live.
- **`restart`/`redispatch` flows** (`workflow.restart`, `workflowGeneration`
  bumps, `inputVersion` bumps) are schema-ready but have no public trigger yet
  — a future "revise inputs"/retry path will use them.
- **P07/P10 integration notes:** worker records should read
  `missionId`+`workflowId`+`workflowGeneration` off decisions/runs for
  correlation; `decisions.resolve` is the only continuation path;
  `checkContinuation` is the re-gate seam for pause/cancel/stale-input
  rechecks; `insertRun`/`finishRun`/`sweepRuns` are the receipt helpers.
  `prospectId`/`conversationId`/`artifactId` are bounded strings pending the
  P09/P10/P11 tables.
- The dev fixture's stage bodies (`devFixtureStage`, `devFixtureBranchStage`)
  are intentionally deterministic and produce synthetic keys — P09 replaces
  the stage bodies, not the machinery.
- The local deployment retains synthetic probe rows; `.env.local` is
  gitignored. First cloud push is a deferred integrator gate.
