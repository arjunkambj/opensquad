### Delivery-uncertainty lifecycle (V18) — full loop exercised

1. `drafts:assignWorkspaceInbox` bound a sender inbox (internal seam; no public
   setter exists) → `reserveSendIntent` → `wait`/`outside_window` → `reserved`
   attempt parked with `nextPermittedAt` and a transactional wake scheduled
   inside the committing mutation.
2. Widened the send window via owner-gated `setSendingPolicy`
   (OCC `expectedPolicyVersion` verified — stale → `CONFLICT`).
3. `dispatchAttempt` → `beginDispatch` flipped `reserved → requesting` and
   returned the exact immutable payload + provider idempotency key
   (`opensquad-send-…`, redacted) + payload hash.
4. Provider call deliberately never performed → `sweepStaleAttempts`
   (`staleAfterMs: 0`) → `uncertain`/`lost_acknowledgement`, reservation marked
   uncertain, `delivery_uncertain` decision opened.
5. Blind re-drive `reserveSendIntent` on the same draft → `blocked`
   `attempt_uncertain` — "never blind-retry" is enforced.
6. `requestReconciliation` → `reconcileUncertainAttempt` replayed the SAME
   idempotency key → AgentMail refused `403 Forbidden` → attempt
   `definitively_failed`/`provider_rejected` (real provider call — a real
   key is configured on the local deployment but the staged inbox does not
   exist upstream). The open `delivery_uncertain` ask was retired
   (`superseded`).
7. `cancelAttempt` on the terminal attempt → `CONFLICT` "only a reserved
   (pre-dispatch) intent can be cancelled".

### Credential/token hygiene

- Public query sweep (`missions:listBoard`, `prospects:list`,
  `conversations:list`, `decisions:list`, `sendAttempts:*`, `leadEvents:list`,
  `workspaces:getCurrent`, `bookings:list`, `suppressions:list`,
  `usage:summary`, `activityFeed:list`) grepped for
  `osw_*`/`osl_*`/`fc-*`/`am_*`/`sk-*`/`Bearer`/private-key patterns: **clean**.
- `console.*` audit: only `convex/integrations/agentmail.ts` logs, and only
  provider IDs (`eventId`, `inboxRef`, `threadRef`, `messageRef`) — the code
  comments state "Provider IDs only — never log addresses or bodies". Local
  deployment runs with `--tail-logs disable`, so log capture itself was
  verified by inspection, not by a captured stream.
- Worker `result` bodies containing credential-pattern strings are refused at
  parse time (above).
- Stored rows carry hashes (`credentialHash`, `leaseToken` never returned by
  any public read); seeds' plaintext tokens exist only in the `devSeedFixture`
  return.

## Findings — defects fixed

1. **Workflow failure reasons stored raw stack traces** (fixed `7ea657c`).
   A seeded sales mission whose Firecrawl retrieval threw produced
   `missionProspects.outcomeReason`, `missions.failure`, `progressSummary` and
   activity summaries containing the serialized Convex error envelope —
   nested JSON, `Error:` prefixes and absolute build paths from the stack.
   `convex/lib/validators.ts` gained `unwrapConvexErrorText` /
   `balancedObjectEnd` / `errorReason` (unwrap nested envelopes, keep the
   first human-readable line, strip `Error:`/`Uncaught`, bound the output);
   `convex/workflows/steps.ts` completion callbacks now pass errors through
   `errorReason` before storing; `convex/integrations/firecrawl.ts` reuses
   the shared unwrapping helper. Post-fix re-runs store e.g.
   `Firecrawl /v2/scrape failed (401): Unauthorized: Invalid token` — one
   readable line, no paths, no envelopes.
