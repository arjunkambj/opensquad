## §4.5 EVIDENCE SYNTHESIS RULE (P21; integrator decision D3)

Recorded verbatim below and, identically, in the doc comment above
`recordResearchEvidence` in `convex/evidence.ts`.

```
`evidence` requires nine columns. `vResearchResult.observations` supplies
exactly ONE of them (`finding`), and its `sourceUrl` is v.optional where the
column is required. The backend therefore synthesizes from ITS OWN Firecrawl
retrieval, which is strictly more trustworthy than trusting a model field.
Column by column, without exception:

  prospectId   The `missionProspects` branch this request was dispatched for.
               NEVER model output. §4.5 requires "prospect was assigned", and
               the branch row IS the assignment record.

  runId        The `runs` row this stage created with `insertRun` — the same
               run the worker request was dispatched under.

  sourceUrl    ONLY an observation citing a page THIS RUN's backend actually
               retrieved becomes an evidence row. The model's `sourceUrl` is
               normalized with `normalizeHttpUrl` and looked up in the map of
               pages this run fetched. An observation with no `sourceUrl`, or
               naming a page the backend never fetched, IS NOT EVIDENCE. It
               may live in the research brief artifact, labelled unsourced,
               and is counted in the returned `unsourced` total.

  retrievedAt  The backend's own retrieval timestamp for THAT page.
               `scrapePage` returns `retrievedAt` as an ISO 8601 STRING while
               `evidence.retrievedAt` is epoch ms bounded by `assertEpochMs`
               (1_000_000_000_000 .. 4_102_444_800_000). Convert with
               `Date.parse(page.retrievedAt)`; a NaN or out-of-range value is
               REJECTED (the observation is dropped and counted in `rejected`)
               rather than stored, and never silently replaced by Date.now().

  excerpt      A span of the BACKEND-RETRIEVED page, re-sliced from the
               wrapper's 4000-char EXCERPT_LIMIT down to
               EVIDENCE_EXCERPT_MAX_LENGTH (2000):
               `page.excerpt.slice(0, EVIDENCE_EXCERPT_MAX_LENGTH)`.
               Writing `markdownExcerpt` straight through is out of bounds,
               and using the model's `finding` here would store a paraphrase
               in a column the schema documents as an excerpt of the source.

  observation  The model's `finding`, with `topic` carried into it:
               `${topic}: ${finding}`, bounded to
               EVIDENCE_OBSERVATION_MAX_LENGTH (1000).

  confidence   NEVER model-supplied. `vEvidenceConfidence` is
               supported | hypothesis | unknown, and its doc comment says the
               union exists precisely to stop "an unlabeled guess stored as
               `supported`". DEFAULT TO "unknown". The exact rule:

                 "supported"  ONLY on this stated mechanical basis — the cited
                              page was retrieved by the backend in THIS run
                              AND the stored excerpt is drawn from that same
                              retrieval AND the retrieval reported a 2xx
                              statusCode AND `markdownTruncated` is false.
                              Nothing about the model's wording contributes.
                 "hypothesis" ONLY where the model labelled it one, i.e. the
                              observation's `topic` begins with the reserved
                              host marker "hypothesis:" that the Researcher
                              role template instructs it to use, per §4.5's
                              "hypotheses labeled".
                 "unknown"    Everywhere else, including every truncated page,
                              every non-2xx retrieval, and every observation
                              whose basis cannot be stated mechanically.

  workspaceId / createdAt   Backend facts. Not gaps.

  artifactId   The result's `artifactIds[]` / `evidenceRefs[].artifactId` are
               opaque worker-supplied STRINGS, never validated document ids.
               Each is `normalizeId("artifacts", …)`-resolved and then checked
               for `workspaceId` AND `missionId` ownership before it is
               stored; a string that fails either check is dropped, not
               stored.

At most RESEARCH_OBSERVATIONS_MAX (12) evidence rows per research result.
`qualification` and its reason are NOT new evidence columns: they belong to
`prospects.qualification` (vQualification) and `prospects.fitReason` (≤2000).
The "concise brief" is an `artifacts` row of kind "research_brief". The
evidence table is not weakened in any way to accommodate the worker shape.
```

### Two decisions taken inside that rule, stated

**Ordering of `hypothesis` against `supported`.** A labelled hypothesis is
never upgraded by a good retrieval. `confidenceFor` tests the marker first: the
model said the finding is a guess, and a guess *about* a page is not the page's
claim. A 2xx untruncated retrieval decides only between `supported` and
`unknown`.

**The rule is mechanical, not asserted.** `recordResearchEvidence` does not let
its caller *describe* the page it retrieved. Every entry in `pages` names a
`providerOperations` row, and the url, retrieval time, excerpt, status code and
truncation flag are read back from **that receipt** — the row Convex itself
wrote when it paid for the page. A receipt that is missing, not `completed`, or
belongs to another workspace or another prospect is never admitted, so no
observation can cite it. The argument is a set of receipts, not a set of
claims. This is demonstrated below with deliberately forged page fields.

`vResearchResult` is **not** widened. Widening it would put `retrievedAt`,
`excerpt` and `confidence` back under model control — the precise thing this
rule removes.

**Cap reconciliation P20 flagged** (`DRAFT_EVIDENCE_MAX_ITEMS = 25` vs
`RESEARCH_OBSERVATIONS_MAX = 12`) is resolved at the caller: the draft stage in
stage 3 passes at most `min(25, 12) = 12` evidence ids, drawn from a
`by_prospectId_and_createdAt` read on that branch's own prospect. `evidence.ts`
enforces the 12 for its own writes today.

## Deviations from the approved design, with reasons

1. **No `prospects.devSeedPipelineFixture`.** Stage 1's
   `workerOperations.devSeedFixture` already seeds workspace → membership →
   employees → confirmed campaign → mission → run → prospects, and takes
   `leadLimit` and `prospectCount`. A second dev seeder would be a second dev
   surface to remove before release for no new capability. Every exercise below
   uses the existing one.

2. **`applyResearchOutcome` takes no `briefArtifactId`.** `prospects` has no
   column for it — `evidence.artifactId` is the declared home for the brief
   link, and `recordResearchEvidence` resolves and ownership-checks it there.
   Accepting an id the mutation cannot store would be a lie in the signature.

3. **`markDraftReady` takes `v.id("drafts")`, not `v.string()`.** The value is
   produced internally by `drafts.createRevision`; it never crosses the worker
   trust boundary, so the id type is correct and workspace ownership is checked
   on top of it. (`artifacts.prospectId` stays a string for the opposite
   reason — see Honest deferrals.)

4. **Observation overflow is reported, not thrown.** `RESEARCH_OBSERVATIONS_MAX`
   is the ceiling on rows; a 13th observation lands in `rejected` with the cap
   named rather than failing the whole research result. A payload past
   `RESEARCH_OBSERVATION_INPUT_MAX` (50) is still refused outright, because that
   one would buy unbounded work inside the caller's transaction.

### The `prospectId` retype

`vBranchCompletion.prospectId` (`convex/workflows/events.ts`) and
`ActivityInput.prospectId` (`convex/activity.ts`) are retype sites named by the
P21 card and are **outside the declared write surface**. Reported, not taken.
`vBranchCompletion` is also a durable workflow event validator: changing it
while a parent is parked on `step.awaitEvent` invalidates that journal. The
sequencing a later card must follow is: (1) drain — zero `missionProspects` rows
with no outcome on a non-terminal mission; (2) backfill or archive every
historical `dev-prospect-*` key, because Convex validates existing documents at
push; (3) one commit spanning `events.ts`, `schema.ts`, `activity.ts` and
`steps.ts` together, since it compiles at no intermediate point; (4) re-verify
the drain before the push completes.

**`artifacts.prospectId` stays a string, permanently.** It crosses the worker
trust boundary as the `x-prospect-id` upload header. `v.id("prospects")` would
turn a routine untrusted-input case into an insert-validation failure and imply
the value was checked when nothing checked ownership. The string column plus a
`normalizeId` + ownership check at the read site is correct, and P21 did not
"fix" it.
