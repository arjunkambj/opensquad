## Manual bridge verification (curl vs. isolated local deployment)

Seeded via `workerOperations:devSeedFixture` (one pending `research`
request bound to a real Workflow continuation event, scoped credential
with all six scopes). Token values are intentionally not recorded here.

| Check | Result |
|---|---|
| `POST /worker/claim` no `Authorization` | `401 UNAUTHENTICATED` |
| Claim with bogus token | `401 UNAUTHENTICATED invalid worker credential` |
| Claim with seeded token | `200` — `claimed:true`, `leaseToken`, `leaseExpiresAt`, validated `input` (schemaVersion 1, `research` operation, prompt, `deadlineMs` constraint) |
| Second claim while slot held | `204` |
| `heartbeat` with wrong `leaseToken` | `409 lease token does not match the holder` |
| `heartbeat` correct | `200 {acknowledged:true, instruction:"continue"}`, lease renewed |
| `activity` event `evt-1` | `200 accepted`; replay with same `eventId` → `200` (deduped, no second event) |
| `result` with wrong digest | `400 resultDigest does not match the canonical result body` |
| `result` correct digest | `200 {acknowledged:true, duplicate:false}` — request `succeeded`, slot released |
| Same `resultId`+digest replay | `200 {duplicate:true}` |
| Same `resultId` with different digest | `409 resultId was already applied with a different digest` (anomaly recorded) |
| New `resultId` on a terminal request | `409 a result was already applied` |
| `heartbeat` on succeeded request | `200 instruction:"stop"` |
| `devExpireLease` then `result` | `409 lease has expired` |
| `sweepExpiredLeases` | request → `uncertain`, slot → `uncertain` (not freed); auto-enqueued `interrupt_turn` because a `currentCodexTurnRef` was recorded |
| `interrupt_turn` claim + `completed {terminated:true}` | request → `failed` (`interrupted`, `retrySafety:"safe"`), slot → `idle` |
| `control/claim` + `control/result` `challenge_issued` | `200`; `runtimeLoginChallenges` row holds `verificationUrl`+`userCode` (owner-only, never in feeds) |
| `challenge_issued` replay same `resultId` | `200 {duplicate:true}` |
| `control/result` `completed {account}` | challenge row deleted; `runtimeConnections.state="ready"`, `codexAccountSummary` recorded; `providerConnections(codex)="ready"` |
| `runtime-heartbeat` with `currentRunId`+`currentCodexTurnRef` | `200`; `agentSessions` row upserted (`scopeKey=run:<runId>`, `codexThreadRef`); connection `lastHeartbeatAt`/`workerPhase` updated |
| `devRotateGeneration` → claim/result with old token | `401 credential belongs to a retired runtime generation` |
| Fresh generation-2 credential | works; body `runtimeGeneration` mismatch → `409 stale runtimeGeneration` |
| Heartbeat-scope-only credential on `/worker/claim` | `403 credential lacks the claim scope` |
| Rapid second claim (<250 ms) | `429 claim polled too frequently` |
| Body > bound | `413 body exceeds the bridge bound` |
| Malformed JSON | `400 body is not valid JSON` |
| `artifact` upload (kind `research_brief`, verified digest) | `200 {artifactId, deduplicated:false}`; same `operationKey` replay → `deduplicated:true`; tampered bytes vs. declared digest → `400` |
| `failure` report | `200`; identical replay → `duplicate:true` |

Mission-state separation confirmed in code: terminal mission states
(`cancelled`/`completed`/`failed`) cancel pending transport work;
`paused` stays unclaimable; `queued`/`active`/`waiting_for_user`/
`waiting_for_runtime` remain claimable — an in-flight turn is NOT stopped
because the business workflow parked on a human decision.

  end-to-end (ledger → REST → outcome record) and `ASCII_API_KEY` is set on
  the isolated deployment, but no disposable Box was created from this
  worktree — create→ready→stop→delete against the live provider remains a
  P03-style live gate. The reconciled-create path (sealed credential →
  identical env rebuild) is implemented but not yet provider-verified.
- No live Codex turn was executed by the daemon (no managed login on the
  isolated workspace). The turn executor composes only methods already
  proven in the P03 live gate (`thread/start`, `turn/start`,
  `waitForTurn`, `turn/interrupt`, `account/login/*`); the unproven seam
  is the whole daemon-in-a-Box loop, which the P07 live gate owns.

## Boundary notes

- No provider credential (ASCII/AgentMail/Firecrawl/OpenAI) is reachable
  in a Box or the worker process: the Box env carries exactly the four
  `OPENSQUAD_*` names; `noEnv: true` withholds inherited creds; the env
  hygiene gate exits 78 on leaks.
- Plaintext worker tokens are returned exactly once at issuance (and in
  the dev fixture output for curl exercise); persisted state holds only
  `credentialHash` + the sealed envelope, which `getStatus`/`devDumpBridge`
  never return.
- Diagnostic drivers (`boxmcp.ts`, `p04gate.ts`, `livegate*.ts`,
  `boxprobe.ts`, `boxcmd.ts`, `boxfinish.ts`) are unchanged and are not
  referenced by `main.ts`/the systemd unit — not part of the employee
  image.
- `convex/workflows/*` untouched; Workflow remains the sole owner of
  stage ordering, retries and durable waits — the bridge delivers
  completions into backend-owned continuation events only.
